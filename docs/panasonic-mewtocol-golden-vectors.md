# Panasonic MEWTOCOL-COM golden vectors

本页记录 Panasonic MEWTOCOL-COM 的软件编解码和共享 COM 只读会话证据。实现边界是 FP 系列常见 ASCII 串口帧、站号、XOR BCC、CR、RD/WD 数据区和 RCS/WCS 单触点；页面只复用主站页已打开的 COM，不能自动开关端口，也不会把软件或单次读取结果当作现场 L2 通过。

## 串口参数边界

- 典型演示格式：`9600 8O1`，最终以 FP 型号/通信口手册为准。
- 站号：`01..32`，两位十进制；不使用 Modbus 站号 0。
- 标准头：`%`；超长帧可使用扩展头 `<`，仍需设备手册确认。
- BCC：从 `%`/`<` 开始到正文末尾逐字节 XOR，追加两位大写十六进制和 `CR`。

## 请求向量

读取 `DT100` 一个字：

```text
%01#RDD001000010055\r
```

写入 `DT100` 一个小端字 `0x0064`：

```text
%01#WDD0010000100640052\r
```

读取触点 `X1F`：

```text
%01#RCSX001F6A\r
```

## 响应向量

`RD` 正常响应返回 ASCII 数据体：

```text
%01$RD640014\r
```

解析结果的 payload 是 `6400`；解析器还会检查响应头、站号、期望命令、BCC 和 CR。`!` 错误响应保留原始两位十六进制 PLC 错误码，不把错误文本当作数据。

## 当前证据边界

- S2/S3：Rust codec、JSONL 路由、Electron IPC allow-list、UI 离线生成/解析、上述向量文档。
- S4 软件会话：`panasonic_serial_read` 只读 RD/RCS、共享 COM、MEWTOCOL CR framing、局部回显剥离、有限超时重试、设备型号/序列号/串口参数人工记录。
- 真实 FP PLC L2：尚未完成；需要记录具体 FP 系列/固件、串口电气层、站号、只读值和厂家工具/抓包比对。
- 不包含：自动打开/关闭 COM、WD/WCS 现场写入、订阅、程序服务、TCP 封装、虚拟 Panasonic PLC、未经批准的现场写入。

## 共享 COM 只读会话

- 先在主站页打开实际 COM；Panasonic 页面不会根据输入框自动打开或切换串口。
- `panasonic_serial_read` 支持 RD 数据字和 RCS 单触点读取；WD/WCS 只允许生成离线帧，不进入串口事务。
- 收集器以 `%`/`<` 开始、CR 结束，最大 2048 字节；若 USB 转换器回显完整 TX，会先剥离本地回显再交给 Rust BCC/站号/命令解析。
- 读取可配置 0..3 次重试；只对超时、串口 I/O 或软件帧边界失败重试，设备 `!` 错误不重试并保留原始码。
- 返回结果包含 TX/RX、耗时、尝试次数、当前 COM 参数和人工填写的 FP 型号/设备序列号；这些记录仍需厂家工具或真实设备重复读作为 L2 证据。
