# Siemens S7 Communication

Status: draft. This page documents behavior confirmed from current Nexus source and tests. Real-device validation is still required before calling this production ready.

`SiemensS7Client` is the primary Siemens client in Nexus. It is implemented on TCP with TPKT, COTP, and S7 Communication framing, and supports the `IBatchReadWrite` extension.

## Supported PLC Families

`SiemensPLCS` currently includes:

- `S7_200`
- `S7_200Smart`
- `S7_300`
- `S7_400`
- `S7_1200`
- `S7_1500`

The constructor sets default slot values from source:

| PLC family | Default slot |
| --- | --- |
| S7-1200 | 1 |
| S7-1500 | 1 |
| S7-300 | 2 |
| S7-400 | 2 |
| S7-200 / S7-200 Smart | Fixed TSAP path in source; audit on hardware. |

## Connection Parameters

Constructor:

```csharp
var client = new SiemensS7Client(SiemensPLCS.S7_1200, "192.168.0.10", port: 102, timeout: 5000);
var connect = client.Connect();
```

Configurable properties confirmed from source:

| Property | Purpose |
| --- | --- |
| `Rack` | Rack number used for automatic TSAP calculation on S7-300/400/1200/1500. |
| `Slot` | Slot number used for automatic TSAP calculation. |
| `ConnectionType` | PG=`0x01`, OP=`0x02`, S7Basic=`0x03` to `0x10`; source default is `0x03`. |
| `LocalTSAP` | Optional override for automatically calculated local TSAP. |
| `DestTSAP` | Optional override for automatically calculated destination TSAP. |
| `MaxPduSize` | Negotiated/held PDU size, source default starts at 240. |
| `ByteOrder` | Data byte order, default `Endianness.BigEndian`. |
| `StringEncoding` | Encoding for encoded string helpers, default ASCII. |

## Address Format

Confirmed by `SiemensS7Address` and S7 address tests:

| Area | Examples | Notes |
| --- | --- | --- |
| DB | `DB1.DBW0`, `DB1.DBD10`, `DB1.DB20`, `DB1.DBX10.2` | DB number is parsed before the first dot. Optional `DB` prefix inside the sub-address is accepted. |
| Input | `I0`, `IW0`, `IB0`, `I0.1`, `EB0` | Maps to S7 PE area. |
| Output | `Q0`, `QW0`, `QB0`, `Q0.1`, `AB0` | Maps to S7 PA area. |
| Marker | `M0`, `MW10`, `MD20`, `MB0`, `M0.3` | Maps to S7 MK area. |
| V area | `V100`, `VW100`, `VD100`, `VB100`, `V100.0` | Intended for S7-200/SMART style V memory. |

Sub-address conventions:

- `.bit` or `Xbyte.bit` selects a bit and sets data size to 1.
- `B` selects byte size.
- `W` selects word size.
- `D` selects double-word size.
- A bare numeric sub-address currently defaults to 2 bytes in the parser.

## Read And Write

Standard typed operations are inherited from the shared Nexus read/write surface and implemented in `SiemensS7Client`:

- Bool
- Int16 / UInt16
- Int32 / UInt32
- Int64 / UInt64
- Float
- Double
- String
- Bytes

Example:

```csharp
var read = client.ReadInt16("DB1.DBW0");
if (!read.IsSuccess)
{
    Console.WriteLine(read.Message);
    return;
}

var write = client.Write("DB1.DBW2", (short)1234);
```

## Bulk And Random Operations

`SiemensS7Client` implements `IBatchReadWrite` and exposes:

- `BatchRead(IEnumerable<string> addresses)`
- `RandomRead(IEnumerable<string> addresses)`
- `BatchWrite(IEnumerable<KeyValuePair<string, object>> items)`

Source comments indicate S7 packets are split with a maximum of 19 address items per package. Tests cover multiple DB addresses and different DB numbers against `SiemensS7VirtualPlc`.

Example:

```csharp
var values = client.BatchRead(new[] { "DB1.DBW0", "DB1.DBW2", "DB2.DBW0" });
var raw = client.RandomRead(new[] { "DB1.DBW100", "DB1.DBW200" });
```

## Strings

Raw string helpers:

- `ReadString(address, length)`
- `Write(address, string)`
- `ReadStringEncoded(address, length)`
- `WriteStringEncoded(address, value)`

S7 string helpers:

- `ReadS7String(address)`
- `WriteS7String(address, value, maxLength: 254)`

WString helpers:

- `ReadWString(address)`
- `WriteWString(address, value, maxLength: 254)`

Current source behavior:

- Raw encoded string helpers use `StringEncoding`.
- S7 String handles the Siemens two-byte length header.
- WString handles a four-byte header and Big Endian Unicode payload.

## Virtual PLC

`SiemensS7VirtualPlc` exists for offline tests. Source comments describe a TPKT + COTP + S7 Communication server for no-hardware testing, with memory areas for DB, inputs, outputs, markers, V area, counters, and timers.

Use virtual PLC tests as development confidence only. They are not a substitute for hardware validation.
