# Nexus 2.0 产品完成路线

> 目标不是把所有工业协议无限加入，而是形成可长期使用、可验证、可维护、可回滚的 Windows 工业通讯工作台。

## “完成”的判定

一个功能只有同时满足以下条件，才标记为完成：

1. 界面、Electron IPC、Rust 核心或本地服务全链路接通，不存在只有入口没有实现的选项。
2. 参数边界、失败路径、资源释放和安全边界有自动测试。
3. `cargo test`、`npm run test:electron`、前端构建及桌面烟雾测试全部通过。
4. 涉及具体 PLC、仪表或转换器时，自动测试与仿真只算软件验证；必须单列真实设备型号、固件、接线、读写结果和抓包，才能宣称实机支持。
5. 发布物有版本号、变更记录、校验值和可回滚的上一版本。

## 当前基线（2026-08-23）

- 自动验证：612 个 Rust 测试、278 个 Electron 测试通过（2026-08-23 复测，含三族路由收口）。
- 已有产品能力：Modbus、三菱 MC、S7、FINS 等核心读写/仿真工具，串口调试、轮询、趋势、导出、网络接口诊断、Ping 和一键串口扫描。
- 已知边界：多条协议仍只有仿真/交叉验证证据；真实硬件矩阵尚未全部验收。README、旧规划和审查报告可能记录历史状态，结论应以本路线、当前测试和实机验收表为准。
- 工具链注意：本机 MSVC 主目录缺少常规桌面 `lib\x64`，Rust 重新链接时需显式加入现有 OneCore 与 Windows SDK 库路径；这应在构建脚本中固化。

### R1：日常使用闭环

- 项目文件：已完成版本化 `.nexus.json` 的新建、保存、另存为、打开、v0→v1 迁移和脱敏导出，可恢复连接参数、显示/轮询参数、多会话、点表、每会话趋势选择、指令任务清单、Modbus/MC/S7 模拟器配置和最近帮助引用。保存、迁移另存和脱敏导出均使用同目录临时文件写入、回读校验和原子替换；打开旧版项目先在内存按黄金样本迁移，原文件保持不变，显式保存后才升级。损坏 JSON 报告路径/行列/偏移且不修改源文件；大小、集合数量和嵌套深度超限 fail-closed；密码、令牌、私钥和 API key 类字段显式拒绝，不会写入项目文件。脱敏导出移除项目名、会话/点位名、主机、串口名、自由文本标签和写入值，但保留协议结构、地址和端口用于问题复现。打开项目只恢复配置与输入状态，不自动连接、轮询、启动模拟器、打开帮助弹窗或执行写入。
- 安全写入：主站 Modbus FC05/06/15/16 已完成写前读旧值、目标/地址/旧值/新值确认、写后同地址回读、本地 JSONL 审计和 5MB 轮转；广播写因无法读旧值/回读被阻止。S7 与 MC 的 CPU RUN/STOP/RESET 使用输入特定词的独立高风险确认并写入同一审计流。
- 故障诊断包：已完成一键导出结构化 JSON 与 TXT 摘要；包含版本/运行时、Rust Core、串口、网卡、项目配置脱敏快照和最近 100 帧，并专项回归公网/私网 IP、IPv6、MAC、序列号与凭据脱敏。
- 会话恢复：已完成最近项目一次性只读恢复。异常退出后重新启动只恢复项目配置、点表、趋势选择、任务清单和视图，明确提示恢复状态；不自动打开串口/TCP，不启动轮询、从站、实时推送或任何写入/CPU 控制。
- 内置帮助：地址基、字节序、串口接线、超时和常见错误码。

### R2：真实设备验收矩阵

按“协议变体 × 设备型号 × 固件 × 传输介质”验收。每项至少覆盖连接、读取、受控写入、超时、断线重连和异常响应。未验收项在 UI 与文档中明确标记为“软件已实现 / 实机待验证”。

优先顺序：

1. Modbus TCP 与 RTU 常见 PLC/仪表。
2. 三菱 FX 编程口、A-1E、MC 3E Binary；传统 MC 与 SLMP 语义分开验收。
3. Siemens S7comm、PPI、Fetch/Write 与 Web API。
4. Omron FINS TCP/UDP。

## 后续功能池

先完成 R0/R1，再按实际用户价值逐项加入：

- TCP 端口探测、路由与网卡绑定诊断（与 ICMP Ping 分开显示）。
- 寄存器地图模板、CSV 批量导入、活动地址发现与变化检测。
- 多会话/多数据区工作区、长期历史趋势与告警导出。
- 可保存的测试脚本和批量报文序列。
- 可选 OPC UA/本地 API 网关，默认仅监听回环地址并带鉴权。

不纳入软件承诺：需要专用硬件或封闭授权栈的现场总线、未经真实设备验证的兼容性声明，以及默认开启的危险写入或远程控制。
