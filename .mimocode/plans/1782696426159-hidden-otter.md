## Phase 1: 严重BUG修复 (Critical Bugs)

### 1.1 ModbusRtuOverTcpClient 线程安全问题
- **文件**: `src/Nexus.Modbus/ModbusRtuOverTcpClient.cs` (lines 87-155)
- **问题**: Stream IO在持久模式下未加锁，两个独立lock操作不原子，未使用AcquireIoLock()或_asyncLock
- **修复**: 
  - 将 `ns.Write()` + `ReadRtuResponse()` 包裹在 `AcquireIoLock()`/`ReleaseIoLock()` 中
  - 合并两个独立的 `lock(_lock)` 为单个原子操作
  - 参考 `ModbusTcpClient` 的 `SendAndReceive` 模式

### 1.2 ModbusRtuClient WriteAsync(ushort) 方法隐藏
- **文件**: `src/Nexus.Modbus/ModbusRtuClient.cs` (line 527)
- **问题**: `new` 关键字隐藏基类方法，通过 IReadWriteDevice 接口调用会绕过正确重载
- **修复**: 
  - 移除 `new` 关键字
  - 检查基类 `SerialDeviceBase.WriteAsync(string, ushort)` 是否 virtual，如果是则用 `override`
  - 如果基类不是 virtual，考虑将基类方法改为 virtual

## Phase 2: 中等BUG修复 (Medium Bugs)

### 2.1 SiemensPpiClient 缺失方法
- **文件**: `src/Nexus.Siemens/SiemensPpiClient.cs`
- **问题**: ReadUInt16、ReadUInt32、ReadInt64、ReadUInt64、ReadDouble 未重写，会抛出 NotImplementedException
- **修复**: 实现这些方法，委托给已有的读取方法（如 ReadUInt16 委托 ReadInt16 并转换）

### 2.2 FX Serial Bool 读写存根
- **文件**: `src/Nexus.Mitsubishi/FxSerialClient.cs` (lines 254-261, 301-309)
- **问题**: 明确拒绝执行 Bool 读写
- **修复**: 
  - 实现 FX 协议的位设备读写（M、S、T、C 等位地址）
  - 或者添加文档注释说明这是已知限制

### 2.3 SiemensWebApiClient 同步阻塞异步
- **文件**: `src/Nexus.Siemens/SiemensWebApiClient.cs` (lines 146-147)
- **问题**: `HttpClient.GetAsync().GetAwaiter().GetResult()` 在同步上下文中会死锁
- **修复**: 
  - 同步路径使用 `Task.Run(() => _httpClient.GetAsync(url)).GetAwaiter().GetResult()`
  - 或提供真正的异步实现

### 2.4 Mc3EBinaryClient Thread.Sleep 轮询
- **文件**: `src/Nexus.Mitsubishi/Mc3EBinaryClient.cs` (lines 141-167)
- **问题**: IO锁内 Thread.Sleep(10) 轮询，最长阻塞500ms
- **修复**: 
  - 从头部解析总帧长度，直接读取剩余字节
  - 或使用 NetworkStream.ReadTimeout 代替手动轮询

## 风险评估

| Phase | 风险 | 缓解措施 |
|-------|------|---------|
| Phase 1 (Critical Bugs) | 修改线程安全代码可能引入死锁 | 仔细分析锁顺序，添加并发测试 |
| Phase 2 (Medium Bugs) | 新增方法可能与现有测试不兼容 | 运行全量测试 |
| Phase 3 (MVVM) | 重构 ModbusTcpViewModel 可能破坏功能 | 保留现有测试，逐步重构 |
| Phase 4 (Design) | 基类 virtual 修改影响所有子类 | 全量测试 + 手动验证 |
| Phase 5 (Tests) | 新测试可能发现更多隐藏问题 | 优先修复，不跳过失败测试 |
| Phase 6 (Infrastructure) | CI 合并可能影响发布流程 | 先在分支测试，确认无影响后合并 |
